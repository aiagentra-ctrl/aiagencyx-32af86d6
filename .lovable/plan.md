

## Plan: Multi-Industry Dynamic AI System

### Summary
Upgrade the `create-demo` API to accept an optional `industry` parameter, make LLM extraction and prompt generation industry-aware (not restaurant-hardcoded), and make the landing page sections + chatbot nav items dynamically adapt to the detected/provided industry.

---

### 1. Edge Function: `create-demo/index.ts` — Accept `industry` + Dynamic Prompts

**Changes:**
- Parse new optional `industry` field from request body
- Pass `industry` to `extractStructuredData` so the LLM extraction prompt is universal (not "restaurant/business data")
- Use industry to generate dynamic system prompt via a new `generateSystemPrompt()` function that calls LLM with tool calling to produce a production-level prompt tailored to the industry
- Fallback chain: user-provided `industry` → LLM-detected industry from scrape → `"general"`
- Replace all hardcoded `"Restaurant"` defaults with the resolved industry
- Replace hardcoded hero subtitle "Answers calls, takes orders, and handles bookings" with industry-appropriate text
- Replace hardcoded chatbot nav items (Menu/Order/Reserve) with industry-specific quick actions generated by LLM

**New function: `generateDynamicContent()`**
Uses LLM tool calling to generate in one call:
- `system_prompt` — production-level, industry-specific AI agent prompt
- `hero_subtitle` — one-liner for the hero
- `problem_statements` — 4 industry-specific pain points (title + description + stat)
- `chatbot_nav_items` — 5 quick action buttons relevant to the industry
- `first_message` — voice agent greeting

This only runs when there's no admin-configured `default_system_prompt` template OR when industry != "restaurant".

**Extraction prompt update:**
Change `"Extract structured restaurant/business data"` → `"Extract structured business data for a {industry} business"` and make `menu_items` no longer `required` (add `products`, `pricing_tiers` as alternative fields).

---

### 2. Database: Add `dynamic_content` Column to `demo_pages`

```sql
ALTER TABLE public.demo_pages ADD COLUMN IF NOT EXISTS dynamic_content jsonb DEFAULT '{}'::jsonb;
```

Stores the LLM-generated dynamic content (problem statements, nav items, hero subtitle) so the frontend can render it.

---

### 3. Frontend: `DemoPage.tsx` — Read `dynamic_content`

- Fetch `dynamic_content` from the demo_pages query
- Pass `industry` and `dynamic_content` to child components

---

### 4. Frontend: `ProblemSection.tsx` — Dynamic Problems

- Accept optional `problems` prop from `dynamic_content.problem_statements`
- If provided, use those instead of hardcoded restaurant problems
- Keep current hardcoded ones as fallback

---

### 5. Frontend: `HeroSection.tsx` — Dynamic Subtitle + Floating Bubbles

- Use `dynamic_content.hero_subtitle` if available
- Replace hardcoded floating bubbles ("Book a table for 4", "I'd like to order") with industry-relevant ones from `dynamic_content`

---

### 6. Frontend: `ChatWidget.tsx` — Dynamic Nav Items

- Accept optional `navItems` prop
- If `dynamic_content.chatbot_nav_items` exists, use those instead of hardcoded Menu/Order/Reserve/Location/FAQ
- Keep current items as fallback for restaurant industry

---

### 7. Edge Function: `chatbot-conversation/index.ts` — No Changes Needed

System prompt is already stored per-chatbot and will now be industry-specific from generation time.
